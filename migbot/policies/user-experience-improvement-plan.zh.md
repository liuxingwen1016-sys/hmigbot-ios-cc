# MigBot（迁移精灵）用户体验改善计划

MigBot（迁移精灵）团队（以下简称"本团队"或"运营方"）作为 MigBot（迁移精灵）软件（以下简称"本产品"）的运营主体，向您（以下简称"您"或"用户"）介绍本产品的用户体验改善计划。本计划旨在通过收集迁移工作过程产物，持续改进 AI 迁移效果与产品质量，为您提供更稳定、更高效的使用体验。

请您在决定是否参与之前，仔细阅读全部内容。您一经同意参与，即视为已知悉并接受本计划全部条款。您有权随时退出本计划（退出即停用本产品迁移功能），方式见**第六条第二款**。

> **重要：参与本计划是使用本产品的前提（二元）。**
> - **参与**（`telemetry_consent: "granted"`）：本产品**可用**，并上报第二条第（一）至（五）类全部工作过程产物。
> - **拒绝**（其他任意状态，含 `/a2h-privacy deny`、`/a2h-privacy off`、`A2H_TELEMETRY_OFF=1`）：本产品的**迁移流水线被禁用**（从 `/a2h-spec` 起拒绝运行），且**不上报任何数据**。
>
> 换言之，**拒绝即停用本产品**；参与与否完全由您决定，但若拒绝，本产品的迁移功能将不可用，亦不会采集或上报任何数据。各类上报内容、用途与脱敏处理均受本计划约束。

**第二条  计划参与内容说明**

2.1 本计划不主动收集个人信息。但请注意：第二条第（五）类迁移会话切片可能包含您在会话中自行输入的内容，**请避免在会话中输入个人敏感信息**。

本产品**仅在您参与（`granted`）时**进行采集与上报；拒绝时本产品停用且不采集任何数据。参与后的上报内容与时机如下：

- （一）**代码行数统计**与应用名称：Android 侧的代码行数与应用名称在您执行 `/a2h-init` 完成项目初始化时即上报；HarmonyOS 侧在 `a2h-verify` 阶段随迁移完成信号补齐。
- （二）**阶段进度标记**与**精确 Token 用量快照**：在各迁移阶段（`a2h-init` / `a2h-build` / `a2h-spec` / `a2h-plan` / `a2h-execute` / `a2h-verify` / `a2h-retrospect`）完成时按阶段上报。
- （三）**迁移报告**：`a2h-retrospect` 阶段（回顾报告）及增量迁移各阶段（增量报告）完成时上传。
- （四）**迁移会话切片**：在迁移会话进行过程中持续增量上传。

为支持上述功能并便于您日后申请删除，本产品在 `/a2h-init` 时生成一个安装标识（`migbot_session_id`），随每次上报一并发送，用作删除句柄与活跃度去重。本产品不进行超出本条所列范围的采集或上报。

2.2 参与本计划后上传的工作过程产物

本产品上传至本团队服务器的工作过程产物包含下列五类，且**严格限定**于下列五类：

（一）代码行数统计（`code-lines.json`）：Android 与 HarmonyOS 两侧按文件后缀分组的代码行数；项目名与应用名；

（二）阶段进度标记（`stage-marks`）：迁移流水线各阶段的开始 / 完成时间戳，用于阶段归属与迁移完成判定；

（三）迁移报告（`docs/retrospect-report-*.md`、`docs/increment-report-phase-*.md`，随上传打包）：`a2h-retrospect` 阶段生成的迁移质量回顾报告及增量迁移各阶段报告，包含 Skill 覆盖率、编译错误模式、API 修正、置信度准确度等迁移过程的统计与复盘；报告文件本身**不含**源代码或迁移中间产物；

（四）精确 Token 用量快照（`usage-v2/<session>.json`）：某次迁移会话中，按 Skill 与子 Agent、并按模型细分的 Token 计数（输入 / 输出 / 缓存）——快照文件**仅**包含 Skill 与子 Agent 名称及 Token 计数。该快照由钩子在每个会话回合结束时**仅在本地**采集，并在每个迁移阶段完成时**按阶段**上传；

（五）迁移会话切片（`session-slice`）：您可以通过多种形式与本产品交互，包括但不限于对话指令、代码编写，以及由 AI 编程助手代您执行多步骤迁移任务的代理会话。您通过这些交互向本产品提交的内容，均属于您的"输入"；输入会产生回复与操作（"输出"），例如代您创建或修改工程文件、执行构建命令。输入与输出以增量切片方式上传。如果您在输入中包含个人信息或引用外部内容，我们将收集该信息，并且这些信息可能在您的输出中被再现。

当您提供输入时——包括上传文件、授予本产品访问第三方服务的权限，或指示本产品检索信息或根据信息采取行动——您有责任确保您拥有这样做的必要权利、许可或授权。

上述五类均为**工作过程产物**——是本产品在迁移流水线运行过程中自动生成或记录的文件与统计信息。其中第（五）类可能包含您项目的源代码与会话内容，请您在决定参与前充分知悉。

**第三条  工作过程产物的用途**

本团队收集前条所述工作过程产物，**仅**用于下列目的：

（一）评估并改进 AI 迁移效果，识别频繁失败的代码模式，补全 Skill 知识库；

（二）复现并修复产品缺陷（Bug）；

（三）监控产品健康度，包括错误率与性能瓶颈。

**第四条  脱敏处理**

4.1 对第（一）至（四）类工作过程产物，本产品在其离开您本机之前，与服务端入库之前，分别进行两次清洗。第（五）类迁移会话切片为**原文上传**，不做客户端侧清洗；其存储与访问控制按第五条执行。

4.2 客户端侧脱敏（适用于第（一）至（四）类）：剥离本机绝对路径（例如 `/Users/<您的用户名>/`、`C:\Users\<您的用户名>\`），统一替换为 `~`；剥离 git 提交者邮箱；不采集任何身份字段。

4.3 服务端侧处理：业务统计仅使用项目级标识（项目名、应用名）；上报来源 IP 用于风控（限流与黑名单）、多用户数据隔离及活跃度统计，不用于识别您的自然人身份。

4.4 本团队不将上述数据用于识别或关联任何特定自然人身份。第（五）类迁移会话切片可能包含您在会话中主动输入的信息，其访问严格受第五条第三款的权限控制与审计约束。

**第五条  数据存储与安全保障**

5.1 存储地点

本产品所收集的全部工作过程产物存储于中华人民共和国境内服务器。数据在传输过程中全程采用安全加密（SSL/TLS）；服务端亦采取相应的安全加密与存储保护措施，文件完整性以 SHA-256 校验。

5.2 加密与防泄露措施

（一）数据传输采用 HTTPS 协议，由 Nginx 前置终止 TLS；

（二）所有运维操作（数据导出、删除、黑名单变更）均落入审计日志留痕。

5.3 访问权限控制

仅本团队**运维人员与核心研发人员**可接触原始数据。所有访问操作均记入审计日志，可事后追溯。

5.4 数据保存期限

（一）原始数据（包括迁移回顾报告、明细指标）：保留期限**不超过 12 个月**，到期由后台任务定期清理或匿名聚合；

（二）脱敏聚合统计指标（按周/月聚合的代码行数、Token 消耗趋势等，不含原始文本）：可长期保留，仅用于产品趋势分析，不含可关联至具体项目的字段；

（三）您退出本计划后：本团队应于收到退出意思表示之日起 **30 个工作日内**删除全部可关联至您本地项目（按项目名匹配）的原始数据；已完成脱敏聚合的统计指标因无法反向关联，不属于删除范围。

5.5 若您要求缩短上述保留期限或加急删除，请通过**第八条**所列方式与本团队联系。

**第六条  您的权利**

6.1 查询与复制权

您本地 `.migbot/metrics/` 目录下保留上传产物的本地副本。您可随时通过下列命令查询：

```
ls .migbot/metrics/
ls .migbot/metrics/usage-v2/                     # 各会话 Token 快照与 .stage-marks.json 阶段标记
ls .migbot/metrics/<run_id>/facts/               # 结构化统计（含阶段标记）
tar -tzf .migbot/metrics/<项目名>/spec-*.tar.gz  # 迁移报告包（仅当已触发上传）
```

第（五）类迁移会话切片取自 AI 编程助手在您本机保存的会话记录文件（`.jsonl` 格式），上传的即为这些文件的字节区间；您可通过 `/a2h-privacy status` 查询参与状态，会话记录文件本身可在本机直接查看。

如本团队已部署 MigBot（迁移精灵）数据看板服务，您可通过看板登录查看与本人项目相关的全部上报记录，并导出原始数据。

6.2 退出本计划的权利

您可随时退出本计划。**退出即停用本产品的迁移功能**，且此后不上报任何数据：

（一）执行 `/a2h-privacy deny`（或 `/a2h-privacy off`），或手工将 `.migbot/config.json` 的 `"telemetry_consent"` 改为 `"denied"`（或 `"off"`）。保存后立即生效。

（二）**一次性退出**：在执行命令之前设置环境变量 `A2H_TELEMETRY_OFF=1`（仅对当前进程生效，不修改持久化配置）。

退出后若希望重新使用本产品，按**第六条第四款**重新参与即可。

6.3 删除权

前款方式仅停止未来上报。如您要求删除已上传至服务端的历史数据，请按**第八条**所列方式向本团队提交删除申请。本团队应于收到申请之日起 7 个工作日内予以处理。

6.4 重新参与权

您可随时通过执行 `/a2h-privacy accept` 或将配置文件中 `telemetry_consent` 字段改回 `"granted"` 以重新参与本计划。

6.5 状态查询权

您可通过 `/a2h-privacy status` 查询当前参与状态及上次变更时间。
