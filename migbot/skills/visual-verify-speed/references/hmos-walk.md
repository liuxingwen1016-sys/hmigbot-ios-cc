# 鸿蒙走查：profile、找控件、配对、弹窗、手驱

## profile（`<work>/cache/input/profile.json`）

| 字段 | 必填 | 说明 |
|---|---|---|
| `bundle` / `ability` | init 已填 | 包名与启动 Ability |
| `root` | 建议 | 根页（每次冷启动都到的首页）上一定在的控件选择器，例如 `{"text": "首页"}`；不写时冷启动后第一个稳定画面算根页 |
| `start_recipe` | 否 | `[{"when": 选择器, "tap": 选择器 \| "back": true \| "wait": 秒, "note": ".."}]`，首次启动才出现的画面 |
| `business_readings` | 否 | `[{"name": "account", "selector": {"text_contains": "账号"}}]`，冷启动到根页时核对 |
| `grant_permissions` | 否 | 默认 true：系统权限框由执行器点"允许/仅使用期间允许"；false 时交模型 |
| `grant_location` | 否 | 默认 false：定位权限点"禁止"（定位成功可能改掉与位置有关的数据） |
| `limits` | 否 | `max_swipes`（每页最多滚几屏，默认 8）、`extra_swipes`（比安卓多滚几屏，默认 2）、`search_swipes`（找控件最多滑几次，默认 4）、`breaker`（默认 3）、`max_minutes` |
| `prefilter` | 否 | `ahash_max`（首屏相似度阈值，默认 10）、`max_pairs_per_batch`（默认 4）、`max_frames_per_batch`（默认 10） |

选择器字段：`text`（整串相等，忽略空白）、`text_contains`、`desc`、`id`（ArkUI `.id()` / key）、`type`（如 `Button`）。

## 走查方法：照安卓树复刻，不重新探索

安卓遍历是探索：点到哪里，哪里就是真值。鸿蒙走查是复刻：目标已知，每一步都要回答"是不是安卓点的那个控件、到没到安卓那一页"。五条原则，下面的做法都从它们推出；遇到新情况先看落在哪条原则里，不为单个应用加特例。追求快：每一步只做有限次尝试，做不到就记缺口继续，不停下来问模型。

1. **认控件 = 认同一个控件。** 按证据由强到弱取**唯一**候选，不唯一就不点：
   - 自身标识：鸿蒙保留了安卓的 resource-id；同文字（忽略空白、忽略数字）；一个包含另一个；文案改过的相似文字（相似度 ≥ 0.6、明显最像、位置相近，且不是安卓同屏另一个控件的文字）。同名多个时比周围文字，再比位置。
   - 旁边的文字：无文字图标看安卓同一行紧挨它的文字（单选、勾选旁的「选项名」）。
   - 屏幕位置：安卓那一屏对应滚动位置上，屏幕比例距离 ≤ 0.07、尺寸相近、不带别的文字的可点控件。
   - 最后才看所在容器：重复控件取同序号的那个，或所在容器文字与安卓重合最多的那个（要明显胜出）。
   - **列表里的项是数据**（安卓 `family_size ≥ 2`）：文字、包含、相似、位置都不用，只认"同类列表（尺寸相近）里的同一位置"，跳过安卓别的单元点过的项；同类项一个都没有记 `content_not_found`（列表为空或两端数据不同，出占位单，列表本身的缺失由上级页对比单负责）。
2. **找的范围 = 安卓控件所在的容器和状态。** 当前屏 → 安卓那一步所在高度上横向滚动的行（左滑找、右滑回来）→ 纵向列表（向下滑最多 `search_swipes` 次，再回顶）。到父单元时：在父页别的视图态，"绝对选择"（Tab、选项）默认从任一兄弟态都能点；找不到时回到父页基础态再找一次（别的选项可能把它藏起来）。到父单元的阶梯：已在父页就用（同页面路径、结构包含度 ≥ 0.5；要基础态时还要求可见文字 ≥ 75% 是父页见过的、选中项一致）→ 点回基础态的选中项（相对控件用反向控件，如"前一天"→"后一天"）→ BACK（每经过一层页面/弹层按一次，视图态不按）→ 冷启动后重放安卓点击路径。安卓到这个单元前先选过别的状态的，按点击路径先补这些前置步骤。
3. **点 = 点它露出来的部分。** 点击点取控件没被后绘制的层（底部标签栏、浮层）盖住的部分；整块被盖住就把列表反向滑一点再找，两次仍盖住记 `control_covered`。
4. **到没到 = 落点有没有目标页自己的内容。** 点后画面（页面路径、弹层、可见文字、结构、选中项）必须变化，不变等 1 秒再看，仍不变记 `no_response`；离开应用记 `left_app`，冷启动后继续。采完核对落点只看各单元自己的文字（很多单元都显示的底栏、公共标题不算）：落点显示了安卓另一单元至少两条自己的文字、重合 ≥ 0.4 且比目标高 0.2 以上，就是点到了别处，记 `wrong_target`，不当到达、不走它的下级；同一页的别的视图态不算别处。根页同理：采到的根页和安卓根单元重合不到 0.4 时警告 profile 可能停在了别的 Tab。
5. **安全 = 只点安卓那类控件。** 鸿蒙候选带删除、支付、确认等词，而安卓那个控件自己的描述（文字、id、旁边的标签）没有，就不点，记 `danger_refused`。

采集：视图态先回到顶部；首屏 + 主滚动容器（最多 安卓竖向帧数−1+`extra_swipes` 屏），安卓采过横向条的也滚鸿蒙的只读横向条。滚动判据与安卓相同：锚点位移多数票，否则退化为节点集变化并标 `degraded`。

配对把握 = 安卓单元文字（数字归一）在鸿蒙截图里出现的比例：≥ 0.4 `confirmed`，≥ 0.15 `weak`，更低 `unconfirmed`，安卓没文字 `unknown`。把握不是 `confirmed` 的对子一定交判图。

## 缺口代码（`state_round-N.json` 的 `gaps`）

| 代码 | 含义 | 出单 |
|---|---|---|
| `control_not_found` | 鸿蒙父页上找不到安卓这一步的控件（含前置步骤） | `CRASH_P<父页>_nav_failed_…` |
| `danger_refused` | 鸿蒙同位置控件是删除/确认类而安卓不是，拒点 | `CRASH_P<父页>_nav_failed_…` |
| `no_response` | 点了对应控件，画面没变 | `CRASH_P<父页>_nav_failed_…` |
| `control_covered` | 控件被上层（底栏、浮层）盖住，滑动后仍点不到 | `CRASH_P<父页>_nav_failed_…` |
| `wrong_target` | 点后落到了安卓另一单元那一页 | `CRASH_P<父页>_nav_failed_…`（`nav_mismatch_type: wrong_target`） |
| `content_not_found` | 安卓点的列表项鸿蒙列表里没有、也没有同类项（列表为空或数据不同） | `BLOCKED_P<页>`（列表缺失由上级页对比单负责） |
| `left_app` | 点击后应用退出或到了别的应用；冷启动后立刻离开前台记在根单元上（`phase: launch`，带设备故障日志路径） | `CRASH_P<页>_app_crash_on_nav`；启动时 `CRASH_P<根页>_app_crash_on_launch`，其余页面出占位单 |
| `capture_failed` | 到了页面但截图失败 | `BLOCKED_P<页>`，下一轮重采 |
| `unreachable` | 父单元回不去（恢复梯用尽） | `BLOCKED_P<页>`；续跑时会重试 |

缺口单元的下级全部记 `blocked`（`blocked_by` 指向它），工单正文列出被挡住的下级。

## 弹窗协议

执行器自己处理：系统权限框（按 profile）、ANR（"等待"→"关闭应用"）、软键盘（BACK）、本次点击该出现的弹层（安卓对应单元也是弹层，或弹层文字与安卓单元重合）。

只有以下情况产生 `VVS_MODEL_REQUEST`：冷启动后根页没出来且画面不是加载中；点击后出现了安卓那一屏没有的弹层。请求目录里有 `request.json`（画面大纲、可点控件、上下文：期望的安卓单元和它的截图路径）、`before.png`、`before.json`。决策写 `decision.json`：

```json
{"action": "tap", "selector": {"text": "以后再说"}, "remember": true, "reason": "更新提示，关闭不影响数据"}
```

- `tap`：`selector` 用 `{"text": ".."}`（必须在弹层上唯一）或 `{"point": [x, y]}`；
- `back`：按返回；
- `continue`：这个弹层就是要采的那一屏（照常采集）；
- `stop`：需要用户（真实支付、敏感数据外传、任务外破坏性操作），执行器保存断点退出。

`remember: true` 时按弹层签名（所属包、层类型、层内文字，数字抹成 #）记住，下次同样的弹层自动处理；记住的规则失效会删掉并重新问。普通引导、信息提示、广告关闭由模型按内容自行处理，不转给用户。动作没生效时执行器会带 `previous_failure` 再问一次。

## drive 步骤

| 步骤 | 说明 |
|---|---|
| `outline` | 打印当前画面大纲 |
| `tap <文字>` / `tap desc:<描述>` / `tap id:<id>` / `tap @x,y` | 点控件；危险词控件要写 `tap !文字`（只在用户授权后） |
| `long <同上>` | 长按 |
| `back` | 返回 |
| `swipe up\|down\|left\|right` | 在主滚动容器上滑 |
| `text <内容>` | 往当前焦点输入框输入（没有焦点时输入到上一次点击的位置），可输入中文 |
| `wait <秒>` | 等待 |
| `start` | 冷启动 + start_recipe 到根页 |
| `clear` | 清应用数据（需 `--allow-clear`，且只在用户要求重置数据时） |
| `capture pair=<安卓单元号> [名称]` | 作为该安卓单元的鸿蒙侧采集（与自动采集同一套滚动和 meta） |
| `capture [名称]` | 采一张没有安卓对应的额外画面（`extra_NNNN_*`） |
