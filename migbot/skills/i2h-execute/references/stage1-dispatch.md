# Stage 1 converter 派发与回收

每页使用 a2h-activity-converter；派发前加载 references/agent-prompts/1-converter.md + references/agent-prompts/_common.md。输入包含 iOS 源码、页面 meta/view、存在时的截图路径、资源映射和对应 UI Spec；source_only/progressive 合成兜底不提供虚构截图，按源码转换并保留低 confidence；优先使用已审计运行时证据。既有同源页面产物可复用，不能以空 sidecar 缺失为由重复生成或阻断。

**批内并行与槽位协调**：批内页面默认全并行派发（页面依赖不约束分批——导航 / 嵌入目标未建由 FWD-REF 兜底；批内单写者保证互不阻塞）；每批所有 Agent 全部完成后执行该批收尾结算（§3b-bis，无编译）。并发上限 = i2h-plan Step 2 宿主表的 HOST_MAX（Claude Code 20 / Codex 8 / DevEco Code 10），converter、worker、closer、hmos-builder、env-prewarm 全部占槽，主线程按七条规则调度：

① 在飞数 = 已派出 − 已返回，派发前心算，不落文件；Codex 上返回的 thread 即 close（未 close 的已完成 thread 仍占槽）。
② Stage 1 空槽用于本批未派出的页面与收尾；Stage 2 Base 仅在 S1-V 收口后按 §4a 启动，不跨过用户选择点提前派发。
③ 一批不必一次派完：先派 min(批大小, HOST_MAX − 在飞) 页，converter 每返回一个补一页，直到本批派完——批的组成、closer、brief 不变，只有派出时刻受节流。
④ 收到宿主超限错误：该单位进等待队列，下一个 agent 返回时重派，不立即重试。
⑤ 每批 converter 全部返回后派一个 Batch closer；按单写者协议收尾成功后再起下一批。
⑥ **空信封 = 中断**：agent 返回但 `task_result` 为空 / 无约定信封（供应商限流或宿主中断，均不带 error 字段）→ 视为该单位未执行，重派同一 prompt 且不计本波成功数（异步当场重派 / 同步并入下一波，见 §4a）；连续 2 次空信封 → 降一档并发再派。
⑦ **卡死回收**：观察点 = 每次回轮（通知到达）或宿主等待工具的有界超时（**120 秒**；不 sleep、不忙轮询）。只有新工具结果、该单位写权文件有变更、新增检查证据才算进展，「正在处理」/ running 标签 / 时间戳变化不算。某单位连续 **300 秒**无可观察进展 → 查其已落盘产物并**催询一次**（要它回：已落盘文件 / 未完成项 / 正在跑的工具）；再 **240 秒**仍无实质进展 → 请求取消，确认其写文件 / 构建子进程已停后按 ⑥ 重派（产物完整可接续则 prompt 附产物路径只续剩余，不重做）。明确 token / context 耗尽、限流、断连 → 立即查产物，不等阈值。同一单位连续两次重派仍同因停滞 → 停自动重试，带产物报告，不拖住其他单位。

**派发模式（§3.0 首次派发时定一次，全程沿用；判不准按同步）**：派发一律带宿主表的**后台派发参数**（该宿主无此参数 = 同步）。按首次派发的返回形态判——**立即回执、结果稍后以通知到达 = 异步**：上述七条按各自条件适用，派完本轮即结束等通知回轮，**不得 sleep / 轮询 / 追问子代理进度**，结束前把「在飞 N 个 + 待派 M 个」写进回复便于接续；**阻塞到子代理完成才拿到信封 = 同步**：规则 ①–④ 不适用，改为一条消息组织一波、波内派满 `min(剩余待派单位, HOST_MAX)`、波间无补位，整波返回后再组织下一波（波的构成见 §4a）。同步模式失去的只是增量返回、不是并行度（同一条消息里的多个派发仍并行执行），因此关键动作是**派满**而非降并发。
