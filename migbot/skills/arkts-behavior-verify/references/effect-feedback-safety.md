# 效果反馈与修复副作用

接通末端效果时，同时检查该效果是否触发原入口或其它消费者。此项属于每批现有源码审查及编辑前后自查，默认单轮同样执行；不增加 reviewer、Quick、业务轮次或应用测试阶段。按当前链涉及的回调、订阅、共享状态、后台任务或展示面选择下文检查；无关项在原生证据中简述不适用依据，不扫描无关全应用代码。

## 先确认通知和命令的方向

沿当前活动实现追踪 `入口 → writer/平台 API → 通知/observer → handler → writer`，包括跨文件封装、间接回调和启动/恢复路径。读集覆盖这些节点；缺少回调 owner 时按原有读集扩展协议处理，不能把未知依赖声明为完整。

区分三种触发源：用户主动请求、启动时应用持久化偏好、外部状态变化通知。通知默认只更新应用内状态；需要从通知回写源头时，必须给出业务必要性、平台语义和收敛条件的源码证据。不能因“调用了正确 setter”就判定闭合，也不能只因 callback 和 setter 同时存在就判定有缺陷。

主题示例：`onConfigurationUpdate → refresh → applyTheme → setColorMode` 可能回到配置通知；把用户主题应用路径复用到系统通知路径，可能让局部设置修复影响所有页面。将“应用主题请求”与“投影收到的主题状态”分开；纯黑等派生样式变化不应无条件重新请求系统色彩模式。具体 API 行为和合法参数仍核对当前 SDK 声明及可用平台文档，不从示例推定所有平台都会循环。

## 编辑前后核对

- **重复通知**：相同状态连续到达时，不重复产生无必要的系统写入、持久化、广播、全量刷新或重建。业务要求的周期事件/独立命令不按“值相同”一概丢弃。
- **收敛及异步**：区分“请求模式”和“系统解析后的模式”，保留跟随系统语义。去重缓存只在调用成功后更新；检查同步重入、等待期间重复请求、旧异步结果覆盖新意图，以及失败后可重试。延时、debounce 或一个仅覆盖同步栈的 busy 标志本身不证明异步反馈已消失。
- **订阅生命周期**：新增 listener/observer 必须说明注册身份、注册次数和释放边界；单例与页面实例按实际生命周期处理，重新进入不能无意叠加订阅。
- **共享影响**：修改公共启动、配置或状态回调时，核对同一方法其它调用方、设置关闭/默认分支、未操作该设置时的行为。只审触发工单的一个开关不足以证明公共补丁安全。

对受影响链做一张精简的事件推演表：首次应用、相同通知重复、不同状态变化、失败后重试；按实际代码补充异步乱序和销毁重入场景。每行记录触发源、应用状态变化、源头写入次数/有界条件及对应路径/方法。静态推演标明是源码推演；只有实际运行过的模拟才报告调用计数，且模拟不等于真机流畅度验证。无需为普通无关入口编造完整矩阵。

## 当前链涉及后台任务时：区分受理与完成

从实际实现确认 `await`/返回值代表请求受理、任务入队还是业务完成，定位成功与失败终态、持久化提交和通知的先后顺序，再追到当前工单涉及的消费者。进度达到 100%、启动 API 返回成功或已有订阅，单独都不证明业务完成与刷新闭合；若源码确实等待任务与提交完成，沿该证据判断，不预设所有异步 API 都只是入队。

核对消费者是否在提交后读取终态，以及进度项移除、失败/取消、页面离开后重新进入时如何更新。不能把“进度项不存在”直接等同成功或失败；应按该链的终态协议解释。需要刷新时使用可靠的提交后通知/终态读取，不用任意延时掩盖提交与读取竞态。仅检查当前任务和受影响消费者，复用已有读集扩展、ownership 和证据字段。

## 当前修复涉及共享宿主时：逐个核对相关展示面

修复公共容器、挂载位置或显隐状态时，分别追踪同一交互链涉及的折叠、展开、弹层等展示面：入口 → 状态切换 → 挂载父节点 → 当前活动路由下的可达性。用静态结构确认目标面在相关路由下可挂载和呈现，再判断隐藏来源面的动作是否合理；不能把一个展示面修好当作整个共享宿主已经闭合。

读取现有工单与根因证据中已指出的关联展示面及其 owner；关键文件缺失按既有读集/范围协议处理。源码已显示目标仍被父容器或路由结构遮挡时，保留静态未决项，不降格成“仅运行时未测”。此项不要求全应用页面遍历或额外设备操作。

## 复用原生证据与结果

Baseline 在原生分析/evidence 中记录反馈路径、SDK 依据和缺陷或不适用理由，供工单冻结真实 owner。Repair 在设置 `implemented/unresolved`，或点击 `root_cause_evidence/effect_role_results` 的现有证据文本中记录编辑后的收敛条件、事件推演和引用；不添加未被原生 schema 支持的顶层字段。Quick 在整轮稳定源码上重新核对该路径，不能继承 Repair 的“已处理”文字。

已确认的反馈/重复副作用或缺少必要收敛证据时，不写 `APPLIED` 或 `CLOSED_LIKELY`。仅将安全的局部补丁按原生 `PARTIAL` 交稿并列出剩余 owner；若补丁本身会引入已知回路，先在私有副本中撤掉该不安全改动，无法形成安全补丁时按原生失败规则收口。不要为了保留 changed_files 或消除告警而删掉合法事件绑定、主题跟随或失败重试。

确定性发布仍只证明字节和原生结果契约通过，不能机械证明无反馈回路。源码证据不足保留静态缺口；编译/安装通过和 Skill 自测通过均不能填补它。真机响应、实际回调频率等未测项如实保留为运行时缺口，不擅自增加设备验收或第三轮。
