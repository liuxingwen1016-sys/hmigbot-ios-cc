# 页面数据输入与交互结果契约

在功能 Spec 的既有「数据流 / 对接点 / 验收标准」中记录实际适用项，不新增必交 sidecar，也不按类别凑测试数量。

## 数据来源与跨页传递

对影响可见内容的数据，沿 Android 源码追溯 producer → transport → consumer → rendering，注明源码符号：

- producer：接口、入口参数、共享状态、缓存或 seed 数据；不要把所有数据都当成当前页新请求。
- transport：路由字段、类型/转换、默认值、生命周期时机；对接点同时记录调用方传值和目标页接值。
- consumer：ViewModel/组件状态及最终列表、选中态或文本。空值时区分合法空态、加载失败和缺失输入。
- Preferences 按 store + key 对账；默认值、预置/导入数据和外部生产者可以合法存在。删除键不算生产数据。动态键或未知 wrapper 记待复核，不猜测写者。
- seed 数据按需核对资源导入、初始化完成、目标平台 DAO 查询和 UI 消费；宿主机 SQLite 行数只证明源资产有数据。异常不能仅吞成空数组而失去错误原因。

例如列表由入口对象携带：保留该传参路径，不为消除空列表另造接口。只读声明无局部赋值是检查线索，不能排除原地修改、外部注入或合法静态状态。

## Action 与适用的负向场景

每个有行为差异的 action 核对前置条件 → 用户动作 → 可观察结果，并引用 Android 实现或已批准差异决策。handler 非空、页面签名变化都不证明结果正确。

按实际功能覆盖：列表合法为空/加载失败；接口空 payload/业务错误/超时；弹窗确认、取消、关闭；重复操作；多展示面状态一致性。不存在的关闭入口不补测试，两个按钮允许复用有正确分流的 handler。无法确认适用性时记待复核，不因缺固定类别而 FAIL。

日历等复合状态分别描述 header、网格月份/选中项和详情的预期关系；城市列表按业务标识和来源定义唯一性，不按显示名机械去重。错误绑定与空 handler 分开归因。

## 启动与异步终态

对阻塞启动或关键交互的外部等待，约定整条操作的等待上限和可操作失败态；不要求给每个同步/本地 await 单独加计时器。SDK 超时不可靠时按需增加应用级 deadline，并取消请求或通过操作版本/失效标记丢弃晚到回调，防止超时、重试、跳过后旧请求再次改状态。

重试/跳过/游客模式以 Android 行为或已批准差异为依据；不能为通过冒烟擅自绕过登录、付费或广告门槛。

## 验证边界

静态候选只作 WARN，不证明运行时正确。需要设备验证时复用 `arkts-ui-verifier`：以真实操作和目标 landmark/业务结果断言为准；测试超时、设备不可用、产品缺陷分别归因。纯截图/sidecar 完备性不代替上述结果。

用户选择运行时冒烟时，只验证已接通的关键路径，正常/断网/未登录分别建立前置状态。等待预算来自具体操作，页面签名不变仍可能是成功的保存、Toast 或选中态更新。测试超时先区分 selector/工具/设备问题；应用退后台或静态页无新帧不直接判卡死，崩溃须关联本应用与本次操作时段的证据。鸿蒙不能套用 Android 的 dumpsys gfxinfo 判据。

复用 UI verifier 的报告和真实失败分类；未测、测试失败、确认产品失败分别记录。没有对应的用户动作或合法门槛仍未满足时保留待验范围，不为通过率绕过前置，不新增必交 runtime-smoke/report.json 或 RUNTIME_* 单。
