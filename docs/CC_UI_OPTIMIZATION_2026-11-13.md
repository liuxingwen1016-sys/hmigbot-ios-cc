# CC iOS 流水线优化交接

## 工具改动

- UI 交付门禁随 CC 包以 Python 运行。安装和升级时校验运行时文件摘要，并验证正式入口。移除 `i2h-execute/scripts/bin` 内旧 Android 门禁。
- Spec 的冻结页面元数据继续使用 `meta.json`。Execute 补采的运行时证据独立写入 `runtime-meta.json`，读取时兼容旧格式。续跑先检查已有阶段和交付摘要。
- Plan 按 UI、Base、Slice 分配带源文件摘要的规格输入。验证中间回执记录候选摘要，已批准 schema-2 清单保留原契约。行为验收按稳定 AC 标识绑定计划、设备、签名包和控件树。
- iOS 运行时采集支持共享 XCUITest 会话和宿主后台作业。只有完整、可核对的采集清单可进入下游。视觉回执复用同时核对截图、上下文和规则版本。
- macOS 发布安装回归共通过 303 项测试。使用实际安装后的两个入口读取 DogWalk 清单，报告一致，项目仍阻断于七份转换报告缺失和一个宿主挂载缺失。

## Cuike 试点

- 续跑修复在独立实验工程验证。第三轮诊断签名包在 Mate80 跑完六个状态场景。豆库筛选与归档空态、豆详情编辑、扫描入口通过。历史详情已可进入并打开和关闭编辑，删除确认的取消仍失败。配方首屏已露出闷蒸和注水，仍缺滴滤。豆库下拉搜索路径仍失败。
- iPhone 17 模拟器的搜索和品鉴软件键盘状态仍缺可见证据。完整 UI 保真度、功能覆盖和两小时端到端目标仍待验收。
- 后续工具问题包括 Plan 为根 Tab 补宿主挂载约束。现有 G1 对显式声明的宿主可准确区分已挂载和缺失。已有旧计划需按原批准范围继续追溯。
