## 2. 本轮合入的工具改造

### P0/P1 门禁与生成约束

文件集中在 `migbot/skills/i2h-execute/`。

1. `ui_obligation_gate.py`
   - 检查沉浸式根容器下页面前景是否有安全区避让
   - 检查 sheet→full-screen 的关闭时序，阻止 close handler 提前打开 cover
   - 检查浮动 Tab 是否退化为只有原生通栏 Tabs
   - 检查 iOS 自定义 Shape/Path 是否退化为圆角矩形
   - 检查 RootView 的 `@ObservedV2` 路由是否被未装饰的 `private router` 持有
   - 检查 `bindSheet`/`bindContentCover` 是否直接使用 `this.router.foo` 派生表达式
   - 检查通用数据库 `count(table)` 是否硬编码查询 `id`
   - 检查关系型数据库是否只有 `CREATE TABLE IF NOT EXISTS` 而没有升级迁移

2. `1-converter.md`
   - 强制 sheet dismiss 后再打开 full-screen
   - 强制 RootView/Tab 页面使用可观察路由和 modal owner
   - 强制 WindowModel/安全区前景 inset
   - 强制周期通知调度幂等
   - 强制数据库升级迁移、真实冷启动和覆盖升级验证

3. `3-worker.md`
   - 增加数据库迁移与通用 count 的参考模板
   - 明确旧表新增列必须使用幂等 `ALTER TABLE` 或等价版本迁移

4. `SKILL.md`
   - 允许 `Index.ets` 承载唯一 WindowModel/avoid-area 宿主，但不能丢失 RootView 交付契约
   - 新增门禁 finding 的阻断规则

真机发现的 P0/P1 缺陷如下。

1. **二次冷启动必现资料读取失败**
   - `DbHelper.count(table)` 对所有表查询 `['id']`
   - `library_metadata` 只有 `key` 主键，没有 `id`
   - 首次启动播种成功，二次启动 metadata count 仍为 0，随后误判数据损坏

2. **RootView 路由驱动的 modal 不响应**
   - RootView 使用未装饰的 `private router`
   - `bindSheet(this.router.recipe !== null, ...)` 等直接使用派生 router 表达式
   - 设置、配方、Brew、BeanDetail、History 和全局消息关闭均无法正常更新 UI
   - BeanLibrary 内部 `@Local adding` 的 Scan sheet 可以打开，证明触摸注入和局部状态机制正常

3. **覆盖升级缺少数据库迁移**
   - 真机原有旧构建的 `brew` 表结构与新代码不兼容
   - `CREATE TABLE IF NOT EXISTS` 没有修改旧表
   - 覆盖安装后出现 SQLite Generic error
